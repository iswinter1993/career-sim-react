# Phase 1.3: 改造 setPositions.js — 12位置定位球站位

**Phase**: 1 (12位置引擎改造)
**优先级**: P1
**阻塞**: P0.3 (positionGroup.js)
**被阻塞**: 无

---

## 描述

将 `engine/lib/setPositions.js` 中所有定位球站位函数（角球、界外球、球门球等）的硬编码位置引用替换为 `positionGroup.js` 的分组函数。

## 背景分析

`setPositions.js` 的定位球站位逻辑中：
- 角球通过 `players[0,1,2,3,4]` vs `players[5,6,7,8,9,10]` 硬编码索引来区分防线/前线
- 界外球通过 `players[5]`, `players[7]`, `players[8]`, `players[9]` 硬编码索引设置位置
- 球门球通过 `playerIndex` 调用 `originPOS[1]` 判断方向
- 点球的非罚球球员站位也是按索引硬分配

核心问题：如果CDM排在 `players[4]` 位置（防线最后一人），他被当作"防守球员"处理；但如果排在 `players[5]`，就被当作"进攻球员"——**不一致的行为完全由数组索引决定而非球员的实际位置**。

## 实现内容

### 文件: `D:\newgame\career-sim-react\src\engine\lib\setPositions.js`

1. **添加导入**:
   ```javascript
   import { getPositionGroup, isDefensivePosition, isMidfieldPosition, isAttackingPosition, isWidePosition } from './positionGroup.js';
   ```

2. **角球站位重构** — 替换硬编码索引逻辑:

   **旧逻辑**: 球员[0-4]回到originPOS，球员[5-10]随机站位
   **新逻辑**: 按位置分组分配角色

   ```
   防守方角球站位:
   - GK: 门线站位
   - CB/FB: 区域防守——近门柱/远门柱/中路
   - CDM: 禁区前沿防守（防远射）
   - CM/CAM: 禁区边缘站位
   - LM/RM: 边路站位，准备反击
   - LW/RW: 中线附近，反击第一点
   - ST: 中线附近，反击箭头

   进攻方角球站位:
   - 全队前压
   - CB: 参与进攻头球争顶
   - CDM/FB: 禁区边缘+后方保护
   - CM/CAM/LM/RM/LW/RW: 禁区内外随机站位
   - ST: 最佳头球位置
   ```

3. **界外球站位重构**:

   旧逻辑直接引用 `players[5]`, `players[7]`, `players[8]`, `players[9]` 等硬编码索引。改为按位置角色分配：
   - 发球者：最近边路的球员（FB或WM优先）
   - 接应者：中场球员（CM或CAM优先）
   - 远点站桩：高个防守球员（CB或CDM优先）
   - 回防球员：防线和防守中场

4. **球门球站位重构**: 保持现有逻辑但使用分组函数统一处理

5. **点球站位**: 保持现有逻辑（正确性不受位置数量影响）

6. **`closestPlayerToPosition()`**: 逻辑不变，该函数已位置无关

7. **`setIntentPosition()` 系列函数增强**:
   - `setDefenceRelativePos()`: 防守球员压缩系数更大
   - `setAttackRelativePos()`: 边路球员X方向扩展更大
   - 使用 `isWidePosition()` 判断边路球员

## 验收标准

- [ ] 角球站位不再使用硬编码球员索引
- [ ] 界外球站位按位置分组分配角色
- [ ] CDM在角球防守时站位禁区前沿
- [ ] CAM在角球进攻时站位禁区附近
- [ ] LW/RW在防守角球时站位边路准备反击
- [ ] 定位球站位逻辑与普通比赛逻辑一致使用分组函数
