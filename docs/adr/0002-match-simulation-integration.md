# ADR 0002 — 比赛模拟系统集成

**日期**: 2026-08-06  
**状态**: Accepted  
**决策者**: 用户 + AI Agent

---

## 背景

当前游戏通过抽象事件选择推进生涯，完全没有比赛模拟。`footballsimulationengine` v5.0.0 已安装在项目中但未集成。需要将回合制比赛模拟引擎集成到现有 React 游戏中，使玩家能够实际参与比赛。

## 决策

### 1. 比赛日作为新的 pending 类型

在现有引擎流程中新增 `pending.type === 'match'` 步骤，与 `event`、`transfer`、`academy` 交替出现。每赛季约 5 场关键比赛。

**Why**: 保持现有引擎架构不变，最小化对 `public/sim.js` 的侵入。比赛日只是另一个待处理步骤。

### 2. 引擎迭代与 Canvas 渲染完全分离

`footballsimulationengine.playIteration()` 是离散调用的，返回完整状态快照。引擎在独立循环中快速运行，Canvas 渲染层通过 `requestAnimationFrame` 从当前快照绘制，不等待引擎。

**Why**: 
- 比赛引擎的迭代速度不应受限于 60fps 渲染帧率。
- 自动模拟时引擎可全速运行，仅定期更新渲染快照。
- 分离后两个子系统可独立调试和测试。

### 3. 球员属性双向映射

玩家球员的 15 项子属性（技术/身体/精神三层）→ `footballsimulationengine` 10 项技能，通过加权映射完成。队友属性随机生成。

**Why**: 
- 保留现有三层分类 UI（技术/身体/精神），用户已熟悉。
- 值域从 0-20 迁移到 0-100 以对齐引擎技能值域。
- 队友随机生成保持简单性，后期预留真实数据接口。

### 4. 赛前战术 + 比赛中暂停介入

玩家可在赛前设置阵型、心态、首发阵容。比赛中随时暂停→修改→继续，共 3 次换人名额。暂停时引擎停止迭代。

**Why**: 
- 赛前设置提供策略深度。
- 随时暂停给予玩家对关键时刻的掌控。
- 3 次换人限制符合真实足球规则，增加决策压力。

### 5. 上下布局的比赛 UI

上半部分：Canvas 2D 俯视比赛动画（22 球员 + 球）。下半部分：Tab 切换（技术统计 / 积分榜 / 播报日志）。

**Why**: Canvas 需要足够大空间渲染流畅的 2D 动画。上下布局比侧边栏布局优先保证动画区域。Tab 切换在有限空间内组织三类信息。

### 6. 赛后评分驱动能力增长（叠加模式）

赛后评分公式：6.0 起评 ± 比赛事件加权 ± 赛果/零封红利。评分触发的子属性增长与现有赛季 `tickAttributes` **叠加**（加法关系）。

**Why**: 
- 让每场比赛的表现立即反馈到球员能力上，增强投入感。
- 叠加而非替代——赛季整体进步 + 单场表现奖励两者并存，模拟现实中的"比赛经验积累"。

### 7. 积分榜嵌入比赛页面侧边栏

预设联赛赛程表，所有球队间比赛按计划推进。玩家比赛嵌入其中，其他比赛自动模拟比分。

**Why**: 给玩家提供完整的联赛上下文，知道自己的表现在积分榜上的意义。

## 后果

### 正面

- 比赛模拟填补了游戏核心空白，从"抽象事件选择器"变成真正的足球生涯游戏。
- 迭代/渲染分离架构为未来性能优化（Web Worker 跑引擎、WebGL 渲染）打下基础。
- 战术介入 + 赛后评分系统让每场比赛都有玩家决策和即时反馈。

### 负面

- Canvas 2D 动画开发复杂度和代码量显著增加。
- 双属性系统（现有点到引擎技能）的映射需要仔细调校。
- 16 人阵容随机生成可能导致比赛结果不够均衡。

### 风险

- `footballsimulationengine` 是纯 Node.js/CommonJS 模块，在浏览器中使用需要 Vite 正确处理 CJS→ESM 转换。`engine.js` 第 89 行有 `console.log` 污染需移除。
- 大量比赛迭代可能导致主线程阻塞，需要考虑 Web Worker 或分帧执行。

## 现状更新 (2026-08-13)

引擎已从 npm 包切换为项目内 ESM fork `src/engine/`（`footballsimulationengine` v5.0.0 的 vendored 改造版）。`src/matchEngine.js` 直接 `import * as Engine from './engine/engine.js'`，不再经 Vite 别名、也不再依赖 npm 包（已 `npm uninstall`）。上述「CJS→ESM 转换」风险已消除；`console.log` 污染已在 fork 内移除。
